# 이라크·중동 업무 뉴스 대시보드

이라크·중동 뉴스를 검색·추천하고, 고른 기사로 한국어 초안을 편집한 뒤 기존 양식의 일일 PPTX와 주간 DOCX를 만드는 로컬 개인용 앱이다. 수집은 버튼을 눌렀을 때만 실행한다(자동 수집 없음).

## 실행

Python 3.11 이상이 필요하다.

```bash
pip install -r requirements.txt
```

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 <http://127.0.0.1:8000> 을 연다. 데이터는 `data/` 아래 SQLite 파일과 생성 문서로 저장된다.

## 하루 작업 순서

일일 PPT 한 건을 만드는 순서다. 목표는 수집부터 파일까지 10~15분이다.

1. **수집**: 추천 기사 화면에서 기간을 정하고 "새 기사 수집". 끝나면 추천 20건 안팎이 보고서 문체로 정리되어 나온다.
2. **고르기**: 구역 버튼(정치·치안·테러·국제…)으로 훑으며 쓸 기사를 체크한다. 추천에 없으면 관심 주제 탭이나 "전체 보기"에서 찾는다.
3. **목록에 없는 사안 넣기**: "직접 항목 추가"로 공식 발표·보안당국 공지처럼 검색에 안 잡힌 사안을 넣는다. 바로 선택된다.
4. **문장 만들기**: 쓸 기사를 눌러 원문을 열고, 본문을 복사해 "원문 본문 붙여넣기"에 넣으면 본문 전체에서 핵심을 뽑아 제목 줄과 하위 항목(`*`, `☞`)을 쓴다. 본문은 저장하지 않는다. 문장이 어색하면 그 자리에서 고친다(고친 문장은 다음 요약의 예시가 된다).
5. **일일 PPT**: "일일 PPT" 화면에서 "이 기간에 선택한 기사 가져오기". 이라크 국내 사안은 '정치 / 치안'에, 국제 사안은 '경제 / 국제'에 한 항목으로 들어간다. 지도 사건이 있으면 "사건 추가" 후 지역명을 넣고 "기억한 위치 사용"을 누른다.
6. **생성**: "저장하고 PPTX 생성" → 내려받아 PowerPoint에서 확인한다. 화면에 "확인할 점"이 뜨면(분량 초과, 줄바꿈 예상) 그 부분을 먼저 본다.

주말 합본은 일일 PPT 화면의 "합본 종료일"을 넣는다.

## 설정

`.env.example` 을 `.env` 로 복사해 채운다. `.env` 는 저장소에 올리지 않는다.

| 이름 | 용도 | 없을 때 |
|---|---|---|
| `ANTHROPIC_API_KEY` | 기사별 한국어 제목·요약(Claude API, 종량 과금) | 화면에 "요약 설정 필요" 표시. 수집·선택·초안·문서 생성은 그대로 동작하고 한국어 제목·요약은 직접 입력 |
| `AUTO_SUMMARIZE` | `0` 이면 자동 요약·묶기를 끄고 버튼으로만 실행 | 자동(켜짐) |
| `LLM_MODEL` | 요약 모델 | `claude-haiku-5-5` |
| `LLM_BODY_MODEL` | 붙여 넣은 본문을 요약하는 모델(기사당 1회) | `claude-sonnet-5-5` |
| `LLM_GROUP_MODEL` | 같은 사건 묶기 모델 | `claude-sonnet-5-5` |
| `DAILY_BUDGET_USD` | 하루 Claude 사용 추정액 한도(달러). 넘으면 자동 요약·묶기를 멈춤. `0` 이면 한도 없음 | `0.5` |
| `SUMMARIZE_KOREAN` | `0` 이면 한국어 기사는 다시 쓰지 않고 원래 제목 그대로 둠 | 다시 씀 |
| `DEMO` | `1` 이면 가상 데이터만 보여주는 데모 모드 | 실제 수집 모드 |
| `DATA_DIR` | 저장 위치 | `./data` |

뉴스 검색은 Google 뉴스 RSS를 쓰며 키가 필요 없다. 검색어·관심 주제·분류 키워드·추천 가중치는 `config/topics.yaml` 에서 고친다. 고친 뒤 앱을 다시 켜면 저장된 기사에도 반영된다.

미리보기에는 LibreOffice(`soffice`)가 필요하다. 없으면 화면에 "미리보기 제한"이 표시되고 파일 내려받기만 된다.

## 화면

- **추천 기사**: 보고서처럼 구역(관심 주제 / 정치 / 치안·테러 / 경제 / 국제)으로 나눠, 항목마다 제목 줄 `날짜, 주체, 조치 (출처, 날짜)` 과 그 아래 세부 줄 `* …` 로 보여준다. 점검이 필요한 요약에는 `☞` 줄이 붙는다. 추천 이유·원문 제목·확인 상태는 항목을 눌러 들어간 상세 화면에 있다. 첫 화면에는 추천 20건만 보이고 "전체 보기"로 기간 내 전부를 연다. 기간(바그다드 날짜)·추가 검색어로 수집, 출처별 수집 상태, 관심 주제 탭(비스마야·한화·NIC / 이라크 내각회의 / 한국 언론), 분류·지역 필터, 기사 선택, 한국어 요약.
- **기사 상세**: 원문 링크, 사실 확인 상태, 추천 이유, 같은 사건으로 묶인 기사, 한국어 제목·요약 직접 수정.
- **보고서 초안**: 선택한 기사로 초안 생성, 편집·저장·복사. 다시 만들 때는 확인을 받고 이전 내용을 이력에 남긴다.
- **일일 PPT**: 사건 목록과 지도 표식 위치, 2장 본문 편집 → PPTX 생성·미리보기·내려받기. 실제 일일 보고서 12건의 관행을 따른다: 사건이 없으면 "특이사항 없음", 주말 합본은 날짜가 "2026. 11. 12 ~ 13"이고 사건 줄 앞에 날짜가 붙는다. 선택 기사를 가져오면 이라크 국내 사안은 '정치 / 치안'에 기사별로, 국제 사안은 '경제 / 국제'에 "美-이란, 역내 분쟁 관련" 한 항목의 하위 줄로 들어간다. Kirkuk·Diyala·Dhi-Qar·Baghdad 는 실제 보고서의 표식 위치를 기본값으로 제안한다.
- **주간 Word**: 구역별 본문, 테러 통계, 유가 표, 영향 문단 편집 → DOCX 생성·미리보기·내려받기.

## 동작 원칙

- **본문을 가져오지 않는다.** 제목·매체·발표 시각·링크만 저장한다. 요약은 "제목 기반"(검색 요약이 있으면 "제목·검색 요약 기반")으로 표시된다.
- **추천은 실제 보고서 구성을 따른다.** 구역별 정원(정치 6 · 치안·테러 4 · 경제 3 · 국제 4)과 관심 주제(비스마야·한화·NIC 전부, 내각회의 최대 2건)로 이틀 기준 20건 안팎을 고른다. 기간이 길면 날수에 비례해 최대 3배까지 늘린다. 보고서에 반복해서 실리는 사안(무장단체 무기통제, KRG–중앙정부, 총리 조치, 주변국 관계, IS 작전, 공격·요격, 에너지 시설, 재정·금융, 美–이란 협상, 국제유가, 한국 관련)이 제목에 걸리면 가점하고 이유에 "관심 사안: …"을 남긴다. 한 사안이 구역을 독차지하지 않도록 사안별 상한이 있고, 보고서가 자주 인용하는 매체에는 소폭 가점한다. 같은 기간에 여러 매체의 제목에 함께 나온 낱말(예: 'Jurf', 'smuggling')은 그날의 주요 사안으로 보고 가점하며, 같은 화제는 추천에 2건까지만 넣는다(`app/salience.py`). 관심 주제 탭이나 필터·검색을 쓰면 추리지 않고 전부 보여준다. 검색어·사안·정원·가점은 모두 `config/topics.yaml` 에서 바꾼다.
- **요약은 사용자의 문체 규칙을 따른다.** `config/style_guide.md`(「현식's Intelligence Briefing Style Guide」 전문)가 요약 지시문이다. 이 파일을 고치면 다음 요약부터 반영된다. 결과는 제목 줄(주체, 핵심행위)과 하위 항목 0~4개, 태그(정치·치안·테러·경제·국제·유가)로 저장되고, 화면과 문서가 `11.13, … (Shafaq, 11.13)` 형태로 날짜·출처를 붙인다. [유가]는 일일 PPT 가져오기에서 빠지고 주간 Word의 유가 동향으로 간다.
- **고친 문장은 다음 요약의 예시가 된다.** 기사 상세에서 제목 줄·하위 항목을 고쳐 저장하면 (원문, 고치기 전, 고친 후)를 기록하고, 최근 10건을 지시문 끝에 예시로 붙인다. 모델이 이유를 학습하는 것이 아니라 고친 예를 보고 따라 쓰게 하는 방식이다.
- **버튼 없이 정리된다.** 키가 있으면 수집 직후, 그리고 추천 화면이나 관심 주제 탭을 열었을 때 요약되지 않은 기사가 보이면 화면이 스스로 요약과 중복 묶기를 실행하고 끝나면 다시 그린다. 분류·지역 필터, 검색, "전체 보기" 화면은 자동으로 돌리지 않고 "보이는 기사 요약" 버튼으로만 실행한다. `.env` 의 `AUTO_SUMMARIZE=0` 으로 자동 실행을 끌 수 있다.
- **중요도와 사실 확인은 별개다.** 추천 점수와 별도로 "단일 출처 · 미확인" / "독립 매체 n곳 보도"를 항상 표시한다. 제목이 같은 재전재는 한 곳으로 센다.
- **시각**: UTC로 저장하고 바그다드 시간으로 표시·필터한다. 발표 시각 확인 / 관측 시각 / 시각 미상을 구분한다.
- **수집 상태**: 수집 성공 / 일부 출처 실패 / 수집 실패 / 빈 결과 / 검색 미설정을 구분한다. 일부가 실패해도 성공한 결과는 저장한다.
- **사건 묶기**는 두 단계다. 먼저 같은 언어에서 제목이 매우 비슷하고 날짜가 가까운 기사를 규칙으로 묶는다. 키가 있으면 추천 목록 안에서 Claude가 언어·표현이 달라도 같은 사건인 기사를 더 묶는다(응답은 서버에서 검증하고 발표일이 3일 넘게 차이 나면 묶지 않음). 기준은 "하나만 읽어도 무슨 일인지 알 수 있는가"이며, 그 일 이후의 새 결정·수치나 반박 보도는 따로 남기도록 지시한다. 원본 기사는 지우지 않는다.
- **묶음은 직접 고칠 수 있다.** 같은 일인데 따로 나온 기사는 체크하고 "선택 기사 묶기"를 누른다. 잘못 묶인 기사는 기사 상세의 "이 기사를 묶음에서 빼기"로 떼며, 뗀 기사는 자동 묶기가 다시 합치지 않는다.
- **요약 점검**: 요약이 원문보다 단계를 앞서 나가거나(협의 → 체결) 원문에 없는 금액성 숫자(3자리 이상·소수)를 담으면 표시한다. 간단한 규칙 검사이며 요약의 사실성을 보장하지 않는다.
- **통계·유가는 입력값만 쓴다.** 주간 테러 통계의 '계'는 입력값의 합이고, 추천 기사 수로 채우지 않는다. 값이 비면 문서를 만들지 않는다. 유가 설명의 상승/하락이 표와 어긋나면 알린다.
- 서버가 요청하는 주소는 `news.google.com`(GDELT를 켜면 `api.gdeltproject.org`)으로 제한하고 리디렉션도 다시 검사한다.

## 문서 양식

`doc_templates/` 의 원본을 열어 내용만 바꾼다. 도형·번호 매기기·표 서식은 원본 것을 그대로 쓴다.

**원본 양식은 저장소에 들어 있지 않다.** 회사 문서이므로 올리지 않았다. 아래 이름으로 `doc_templates/` 에 직접 넣어야 문서 생성이 된다(자세한 순서는 `doc_templates/README.md`).

| 파일 | 내용 |
|---|---|
| `daily_template.pptx` | 일일 PPT 원본(2026.11.10자) |
| `weekly_template.docx` | 주간 Word 원본(2026.11.12자) |
| `daily_base_slide1.png` | 지도 위치 지정 화면의 바탕 그림. 양식을 넣고 앱을 켜면 자동으로 만들어진다(LibreOffice가 있으면 슬라이드 전체, 없으면 원본의 지도 그림만 합성). 양식을 바꿨으면 이 파일을 지우고 앱을 다시 켠다 |

양식을 바꾸면 `app/config.py` 의 양식 버전 값도 올린다. 생성 이력에 버전이 함께 기록된다.

DAILY_PPT_SPEC.md 와 WEEKLY_WORD_SPEC.md 는 받지 못했다. 생성 규칙은 원본 파일 4개의 구조에서 직접 확인한 것이다.

## 요금

**검색(수집)은 무료다.** Google 뉴스 RSS는 키도 요금도 없다. 요금은 Claude API 호출(요약, 같은 사건 묶기)에서만 나간다. 줄이기 위해 다음과 같이 동작한다.

- 요약은 값싼 모델(Haiku 5.5)을 기본으로 쓴다. 문체가 부족하면 `.env` 의 `LLM_MODEL=claude-sonnet-5-5` 로 올린다(단가 약 20배).
- 기사 10건을 한 번의 호출로 보내고, 긴 문체 규칙에는 프롬프트 캐싱을 건다. 추천 20건이면 요약 2~3회 + 묶기 1회다.
- 한 번 요약한 기사는 다시 호출하지 않는다. 추천 구성은 규칙으로만 정하므로 요약한다고 목록이 바뀌어 다시 요약하는 일이 없다. 한 번 실행에 최대 30건이다.
- 화면 상단에 "오늘 Claude 호출 N회 · 약 $0.0XX / 한도 $0.50 (추정)"이 보인다. 응답의 실제 토큰 수에 `config/topics.yaml` 의 `llm_prices` 단가를 곱한 **추정치**다. 실제 청구액은 Anthropic 콘솔에서 확인한다.
- 하루 추정액이 `DAILY_BUDGET_USD` 를 넘으면 자동 실행을 멈춘다. 버튼으로 직접 누른 것은 실행된다.

## 추천 점검

실제 보고서에 실린 사안이 수집·추천되는지 대조하는 도구가 있다. 가중치나 검색어를 고친 뒤 좋아졌는지 숫자로 본다.

```bash
python scripts/audit_recommend.py
```

기준 파일은 세 개다(`tests/fixtures/`). 기준 기간을 먼저 수집해 두어야 하고 API 는 부르지 않는다. 새 보고서의 사안을 같은 형식으로 더하면 기준이 늘어난다.

- `report_items.yaml`: 11.12자 주간 보고서 주간의 14개 사안
- `report_items_1029.yaml`: 10.29자 주간 보고서 주간의 16개 사안
- `report_items_daily_1113.yaml`: 11.12~13 일일 보고서의 6개 사안. **실제 사용 조건**(이틀 기간, 추천 20건 안팎)이다.

## 확인하지 못한 것과 한계

- **Claude 요약**: 사용자 컴퓨터에서 실제 호출로 요약과 같은 사건 묶기가 동작하는 것을 확인했다(2026-11-12, 당시 Opus 5.5). 그 뒤 바꾼 것들 — 문체 규칙 지시문, 10건 묶음 호출, 프롬프트 캐싱, Haiku 5.5 — 은 **실제 호출로 확인하지 못했다.** 개발 환경에서는 실제 호출을 할 수 없어 가짜 서버로 요청 형식과 흐름만 확인했다. Haiku가 문체 규칙(주체·대상·확실성 보존)을 지키는지, 캐싱이 실제로 적용되는지(사용량의 캐시 읽기 토큰), 실제 요금이 얼마인지는 사용해 보며 확인해야 한다.
- **자동 요약은 제목만 보고 만든다.** Google 뉴스 RSS는 본문을 주지 않고 링크도 실제 기사 주소를 공개하지 않아 본문을 자동으로 가져오지 못한다. 그래서 자동 요약은 "제목을 보고서 문체로 옮긴" 수준이고 하위 항목이 거의 없다. 문체 규칙 11절 8항("제목만 읽고 요약하지 않는다")을 지키려면 기사 상세에서 **원문 본문을 붙여 넣어** 요약을 다시 만들어야 한다. 붙여 넣은 본문은 요약 입력으로만 쓰고 저장하지 않는다.
- **PowerPoint·Word에서의 최종 외관은 확인하지 못했다.** LibreOffice 렌더링만 봤고 이 환경에는 원본 글꼴이 없다. 특히 다음은 실제 프로그램에서 확인이 필요하다.
  - PPT 사건 목록에서 문장이 길어 줄이 바뀌면 그 아래 사건의 목록 표식이 어긋날 수 있다(경고 표시).
  - PPT 2장 본문은 상자 크기가 고정이라 분량이 많으면 넘친다(경고 표시, 글자 크기는 줄이지 않음).
  - Word 하위 줄은 원본의 수동 줄바꿈을 글자 폭으로 어림해 끊는다. 줄 끝이 원본과 조금 다를 수 있다.
- **GDELT는 기본으로 꺼 두었다.** 연결 코드는 있으나 시험 중 호출 제한(429)과 연결 끊김이 잦았다. 언어 제한을 넣은 뒤로는 성공 응답을 받지 못해 그 부분은 미검증이다. `config/topics.yaml` 에서 켤 수 있다.
- Google 뉴스 RSS는 본문 요약을 주지 않아 대부분 "제목 기반"이다. 링크는 Google 뉴스 경유 주소다.
- 이라크 총리실·NIC 등 공식 사이트를 직접 수집하지는 않는다. Google 뉴스 검색에 잡힌 것만 들어온다.
- 분류·지역·관심 주제는 키워드 규칙이라 틀릴 수 있다. 기사 상세에서 분류를 고칠 수 있다.
- 초안의 "핵심 요약"과 주간 "그룹 / 건설에 미치는 영향"은 자동으로 쓰지 않는다.
- 다중 사용자, 자동 수집·정시 브리핑, 외부 접속은 만들지 않았다.
